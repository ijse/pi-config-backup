# Pi 全局代理规则

## 依赖与环境

环境信息可参考 `/skill:env-info`（如已安装）。

执行命令需要安装依赖时：
- **禁止全局安装**，除非用户明确要求。
- 本地无可用时，优先创建项目本地环境，不破坏全局环境。
  - Node.js 优先用项目内包管理器；无约束时用 `pnpm`。
  - Python 优先用 `uv` / 虚拟环境，安装到项目本地。
- 不要把密钥、token、cookie 打印到最终回复；读到敏感信息时只说明检测到配置。

## Pi 插件使用偏好

- 多步骤任务优先使用 `todo` 跟踪，完成一项立即更新状态。
- 需要先确认方案时使用 `/plan` 或 plan-mode 工具；用户确认后再执行写入。
- 长目标可使用 `/goal`，完成时用 `goal_complete`，真实外部阻塞才用 `goal_blocked`。
- 需要网页搜索 / 抓取时优先使用 `web_search`、`fetch_content`、`source_check`。
- 需要 MCP 时先用 `mcp({})` 查看状态，再搜索/描述具体工具；不要假设 MCP 服务器已连接。
- 处理图片、音视频或截图时可用 `analyze_image` / `/multimodal-proxy`。

## 子代理（Subagents）

- 子代理指南见 `~/.pi/agent/agents/README.md`。
- 默认以最小权限授权子代理：探索只给 `read, grep, find, ls`。
- 只有边界明确的实现任务才给 `edit/write/bash`，主代理必须复核 diff 和测试。
- 并行子代理不得修改同一批文件；并行写入前先拆分所有权。

## 独立测试

- 主代理处理新增功能、行为变更或 Bug 修复时，先读取 `~/.pi/agent/skills/independent-testing/SKILL.md`。默认由独立 Subagent 负责测试方案设计、测试代码编写与执行，主代理负责生产代码、协调和最终复核；不要等实现完成后才安排测试。
- 测试以需求和接口契约为依据，不以当前实现为正确答案。明确文件所有权；主代理不得为让测试通过而擅自削弱断言、跳过或删除测试。
- 纯文档、纯格式等确定不影响行为的改动可豁免，并简述原因；不能仅因“改动小”跳过有行为变化的独立测试。项目规则可细化测试命令、目录与风险要求。
- 工具不可用、子代理失败或测试环境受阻时，明确报告独立验证缺口；需要改由主代理编写测试时先征得用户同意，不得把自测冒充独立验证。没有实际执行证据，不得宣称测试通过。
- 本节委派要求仅适用于主代理；子代理完成所分配的测试或审查任务，不再嵌套委派。该流程是行为约束，不是文件沙箱或 CI 硬门禁。
